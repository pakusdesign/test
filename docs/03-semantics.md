# Семантический анализ

## Поток

Аудио → STT → редактируемый текст → модель извлечения → проверка схемы и источников → расчёт полноты → проверка пользователем → подтверждённые факты → генерация.

Модель не определяет процент. Модель предлагает факты и смысловые единицы. Сервер проверяет результат. Пользователь подтверждает его. Это снижает ошибки, но не гарантирует истинность всех выводов модели.

## Единицы полноты

| ID | Условие заполнения |
|---|---|
| q1.task1 | Есть первая конкретная ежедневная задача: действие и объект |
| q1.task2 | Есть вторая отличающаяся конкретная ежедневная задача |
| q2.project | Назван или однозначно описан текущий проект |
| q2.contribution | Указан вклад сотрудника или результат работы в проекте |
| q3.direction | Ясно: продолжает текущий проект или переходит на другой |
| q3.project | Для продолжения разрешена ссылка на определённый q2.project; для перехода нужен новый проект |
| q4.tools | Назван конкретный инструмент/программа либо прямо сказано, что специальных инструментов не требуется |
| q4.knowledge | Названо конкретное знание/умение либо прямо сказано, что специальных знаний не требуется |

Один факт может содержать несколько единиц только при наличии явного основания. Третью и последующие задачи сохрани в результате, но они не повышают процент сверх 25% за вопрос. Не требуй одновременно инструмент, программу и знание: инструмент и программа относятся к одной категории.

«Он работает с задачами» не заполняет q1.task1. «Проверяет счета поставщиков» заполняет. «Python» заполняет tools, но не даёт права автоматически добавить анализ данных в knowledge.

«Не знаю» означает unknown и не повышает полноту. «Специальные программы и знания не нужны» может явно закрыть обе единицы q4 как not_required. Не используй not_required для задач, проекта и плана.

## Формула

Каждая единица даёт 1, если: состояние known или разрешённое not_required; есть действительные ссылки на факты; факты подтверждены; нет противоречия; зависимости актуальны. Иначе — 0.

`completeness = 100 * sum(valid_units) / 8`

Для каждого вопроса: 0/2 = empty, 1/2 = partial, 2/2 = complete. Статус answered хранится отдельно: пользователь проверил ответ или явно пропустил вопрос. Пустой ответ можно пропустить, но нельзя назвать содержательно полным.

## Источники

Факт имеет id, questionId, kind, text и evidence[]. Источник содержит answerId, answerRevision и дословную непустую quote из текущего текста. Сервер проверяет существование ответа, совпадение версии и наличие цитаты. Цитата подтверждает происхождение текста, но сама по себе не доказывает корректность перефразирования.

После редактирования ответа все факты с его старой версией теряют подтверждение. Анализ повторяется по всем актуальным ответам. Не теряй уже подтверждённые независимые факты: сохраняй их подтверждение только при точном совпадении канонического содержания, источников и зависимостей. ID фактам назначает сервер.

Уточнение хранится отдельным answerId с тем же questionId. Не заменяй исходный ответ автоматически. Правка исходного ответа увеличивает answerRevision. Для разрешения конфликта пользователь явно редактирует ответ или помечает старый ответ как superseded; только активные ответы участвуют в анализе.

## Противоречия и зависимости

«Продолжит текущий проект» и «Перейдёт в другой проект» без явного исправления дают conflict. Система не выбирает последний вариант молча. Связанные единицы не дают прогресс до разрешения конфликта.

Факт q3 о том же проекте ссылается через dependsOn на факт q2. После изменения или удаления q2 пересчитай q3 и запроси подтверждение. Ответ на один вопрос может содержать сведения для другого: разрешай это, показывай источник и проси подтверждение. Не пропускай обязательный экран вопроса без проверки пользователем.

## Уточнения

Сервер выбирает первую незаполненную единицу текущего вопроса. Используй короткие шаблоны:

- q1.task1: «Назовите одну ежедневную задачу: что сотрудник делает и с чем работает?»
- q1.task2: «Какую ещё задачу он выполняет ежедневно?»
- q2.project: «Какой проект вы имеете в виду?»
- q2.contribution: «За какой результат в этом проекте отвечает сотрудник?»
- q3.direction: «Он продолжит текущий проект или перейдёт на другой?»
- q3.project: «Как называется или что делает этот проект?»
- q4.tools: «Какие программы или инструменты нужны? Можно указать, что специальных инструментов нет».
- q4.knowledge: «Какие специальные знания нужны? Можно указать, что они не требуются».

Для conflict покажи оба варианта и попроси выбрать или исправить текст. Не требуй от пользователя терминов «семантика», «единица» и «пайплайн».
