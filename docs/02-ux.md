# Интерфейс и состояния

## Композиция

Один экран содержит один основной вопрос. Центр экрана: круг, номер вопроса, формулировка, короткая подсказка и кнопка записи. Под ним доступны «Ответить текстом» и «Назад». После обработки появляется редактируемая расшифровка и карточка фактов.

Визуальный ориентир — круговой прогресс Apple Face ID. Используй собственную графику. Не показывай сканирование лица или биометрическую проверку.

Обязательный стиль — glassmorphism. Компоненты — Carbon с кастомизацией. Токены, компоновка и допустимые изменения описаны в [дизайн-системе](10-design-system.md). Нулевые, пустые, ошибочные и сетевые состояния описаны в [матрице состояний](11-interface-states.md).

## Состояния

| Состояние | Текст и действие |
|---|---|
| ready | «Нажмите и расскажите». Кнопка «Записать ответ» |
| requesting_permission | «Разрешите доступ к микрофону». Доступна отмена |
| recording | Таймер, реакция на громкость, кнопка «Завершить запись» |
| transcribing | «Преобразуем речь в текст» |
| analyzing | «Проверяем, хватает ли сведений» |
| review | Расшифровка, факты, кнопки «Подтвердить» и «Исправить» |
| clarification | Один вопрос, голосовой и текстовый ответ |
| error | Конкретная ошибка, повтор и текстовый ввод |
| overview | Четыре карточки, полнота, пропуски, переход к исправлению |
| generating | «Составляем описание вакансии» |
| result | Разделы описания, неизвестные данные, редактор, экспорт |

Переход записи: ready → requesting_permission → recording → transcribing → analyzing → review. После отказа микрофона: error → ready или текстовый редактор. Не запускай микрофон автоматически после ошибки.

После правки текста запусти новый анализ по кнопке «Проверить ответ». Пока анализ не завершён, «Подтвердить» недоступно. При подтверждении зафиксируй факты и обнови круг.

После неполного ответа предложи уточнение. Доступны «Дополнить» и «Продолжить без уточнения». Автоматически предлагай не более двух уточнений на исходный вопрос. Затем покажи доступные действия без цикла. Пользователь может сам вернуться к вопросу.

## Круг

Круг содержит четыре равных сегмента по 25%. Каждый сегмент содержит две смысловые единицы по 12,5% общего круга. Формула находится в semantics. Отображай округлённое целое число; расчёт храни без округления.

До подтверждения показывай предварительные факты, но не меняй подтверждённый прогресс. В центре: «Полнота 63%». Рядом: «Проверено ответов: 3 из 4». Это разные показатели.

Внешний ореол реагирует на громкость только во время записи. Он не меняет заполнение сегментов. Во время обработки показывай один Carbon InlineLoading рядом с подписью этапа под кругом. При reduced motion используй статичную отметку ожидания. Не анимируй ложный процент загрузки.

При удалении факта прогресс может уменьшиться. При смене текущего проекта зависимое «тот же проект» в ответе 3 требует повторной проверки.

## Движение

Подробная спецификация круга находится в [требованиях к анимации](12-progress-animation.md). Заполнение: 400 ms, cubic-bezier(0.22, 1, 0.36, 1); снижение: 240 ms с той же кривой. Смена вопроса: opacity и translateY до 8 px за 180 ms. Не задерживай доступность кнопок ради анимации. Останови Web Audio, requestAnimationFrame визуализатора и media tracks при завершении или отмене записи и размонтировании. Смена сетевого этапа сама по себе не завершает локальную запись.

При prefers-reduced-motion отключи пульсацию, перемещение и плавное заполнение. Показывай конечное состояние сразу. Частота визуализатора — целевые 30–60 кадров/с; это не гарантия без измерения.

## Ошибки и ограничения записи

Максимум 120 секунд и 10 MiB на ответ. При достижении лимита заверши запись и предложи обработать записанное. Не обрезай текст молча. При тишине: «Не удалось распознать речь. Запишите ответ ещё раз или введите текст».

Если пользователь отменяет запрос, поздний ответ не должен менять экран. При уходе со страницы во время записи предупреди о потере несохранённого ответа там, где браузер позволяет.

## Доступность и адаптация

Поддерживается только desktop. Основные проверяемые ширины: 1024, 1280, 1440 и 1920 CSS px без горизонтального скролла. При узком окне и увеличении масштаба сохраняй доступ к содержимому через перестроение в одну колонку. Отдельная мобильная версия не требуется. Все действия доступны клавиатурой. У кнопок есть подписи и видимый фокус. Прогресс использует role=progressbar и aria-valuenow. Текстовые состояния объявляй через aria-live=polite. Не объявляй каждый кадр визуализатора. Цвет дублируй текстом или значком. После смены вопроса переводи фокус на его заголовок.

На обзоре можно создать неполный черновик при наличии хотя бы одного подтверждённого факта. Подпись: «В описании останутся пропуски». При отсутствии фактов генерация недоступна.
