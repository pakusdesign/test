# Дизайн: glassmorphism и Carbon

Версия требований: 1.1. Эти требования обязательны. Они уточняют UX и заменяют прежнее требование мобильной компоновки.

## DES01. Визуальный стиль

Используй glassmorphism: полупрозрачные панели, размытие фона за панелью, тонкую границу и мягкую тень. Создай ощущение глубины без снижения читаемости. Фон — светлый, с двумя крупными статичными пятнами голубого и сиреневого цвета. Не используй фотографии и непрерывно движущиеся градиенты.

Применяй стекло к основной панели вопроса, панели обзора и контейнеру результата. Не накладывай несколько размытых панелей друг на друга. Вложенные карточки используй с обычной заливкой. Поля, кнопки, меню и уведомления должны иметь достаточную непрозрачность.

Одна светлая тема входит в объём. Тёмная тема не требуется. Не добавляй переключатель без реализации второй темы.

## DES02. Основа компонентов

Используй настоящие React-компоненты Carbon из @carbon/react. Не заменяй их визуально похожими самописными элементами. Выбери совместимую стабильную версию и зафиксируй её. Проверь названия экспортов и props в установленной версии.

Carbon позволяет менять оформление через токены темы. За основу возьми White. Сохрани семантические роли токенов: основной текст, вторичный текст, слой, граница, фокус и статус. См. [Carbon Themes](https://www.carbondesignsystem.com/building-blocks/foundations/themes/overview).

| Задача | Основа Carbon | Допустимая кастомизация |
|---|---|---|
| Основное и вторичное действие | Button | Акцент через тему; отступы в контейнере |
| Голосовой ввод | Button с иконкой микрофона | Расположение под кругом; текст «Записать ответ» / «Завершить запись» |
| Текст ответа и редактор | TextArea; TextInput для заголовка | Размер по контейнеру; непрозрачный слой |
| Состояния фактов | Tag и текст | Текст статуса; смысл цветов сохраняется |
| Ошибка действия | InlineNotification либо ActionableNotification | Контекстное размещение; постоянная видимость до решения |
| Короткий успех | ToastNotification | Например «Текст скопирован» |
| Ожидание | InlineLoading; Skeleton только для ожидаемого содержимого | Подпись этапа; без фиктивного процента |
| Источники и сведения | Accordion | Панель источников в обзоре |
| Очистка или замена правок | Modal | Свои заголовок, объяснение и действия |
| Контекстная подсказка | Tooltip | Только дополнительная информация |
| Компоновка | Grid и Column либо совместимая CSS-сетка | Desktop-композиция из раздела DES04 |
| Круг полноты | Собственный SVG-компонент | Четыре сегмента, восемь единиц; доступность по UX |
| Стеклянная панель и пустое состояние | Собственная композиция | Carbon-типографика, иконки и кнопки |

Круг — единственный специальный индикатор смысловой полноты. Не пытайся использовать обычный спиннер для отображения полноты. Не добавляй вторую библиотеку компонентов.

Сохрани штатные hover, active, focus, disabled, invalid и loading состояния. Не меняй DOM и клавиатурную модель Carbon ради стиля. Стили панели держи в отдельном слое приложения. Не изменяй файлы пакета и не используй глобальные переопределения внутренних CSS-классов.

## DES03. Токены приложения

Значения ниже — проектные решения, а не стандартные значения Carbon. Храни их централизованно. Имена с префиксом app — собственные токены; не выдавай их за API Carbon.

| Токен приложения | Начальное значение | Назначение |
|---|---|---|
| app-canvas | #F4F7FC | Фон |
| app-glass-surface | rgba(255,255,255,0.78) | Главная панель |
| app-glass-border | rgba(255,255,255,0.85) | Декоративная граница панели |
| app-glass-blur | 20px | backdrop-filter |
| app-glass-shadow | 0 12px 40px rgba(22,42,78,0.08) | Глубина панели |
| app-panel-radius | 20px | Скругление крупных панелей |
| app-solid-surface | #FFFFFF | Поля и fallback |
| app-text-primary | #161616 | Основной текст |
| app-text-secondary | #525252 | Вторичный текст |
| app-accent | #0F62FE | Основное действие и заполнение круга |
| app-content-max | 1584px | Максимальная ширина общей сетки |
| app-reading-max | 680px | Максимальная ширина текста вопроса |

Цвета состояний, интерактивные границы, disabled и фокус бери из семантических токенов Carbon. Свяжи их с темой через поддерживаемый API текущей версии. Белая граница стекла декоративная: она не заменяет видимую границу поля или индикатор фокуса.

Используй IBM Plex Sans с локальной загрузкой и системным fallback. Иконки — из Carbon. Проверь наличие русских символов. Типографика: основной текст 16px / 24px, подписи 14px / 20px, заголовок вопроса 28px / 36px, крупный заголовок 32px / 40px. Сопоставь размеры с доступными типографическими токенами и документируй отличия. Отступы: 8, 16, 24, 32, 48px.

Основные кнопки используй в размере Carbon с высотой 48px. Иконка без подписи допустима только для второстепенных действий с доступным именем и подсказкой. Для записи и отправки используй текстовую подпись.

## DES04. Только desktop, адаптивная компоновка

Основной диапазон полной поддержки: ширина viewport от 1024 CSS px. Это ширина области браузера, а не физического монитора. Компоновка должна оставаться удобной на 1024, 1280, 1440 и 1920px. Максимальная ширина содержимого — 1584px; на большом мониторе увеличивай внешние поля.

Основа — 2x Grid. Carbon задаёт desktop-пороги 1056, 1312 и 1584px. Порог 1024px ниже — собственное расширение проекта. См. [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview).

| Ширина viewport | Компоновка |
|---|---|
| 1024–1055px | Компактный desktop; внешние поля 24px; одна основная колонка |
| 1056–1311px | 16-колоночная сетка; одна центральная панель; источники под ответом |
| 1312–1583px | Вопрос остаётся по центру; обзор и результат могут иметь две панели: 10 колонок текста и 6 колонок источников |
| От 1584px | Центрированная сетка до 1584px; ширина текста ограничена; боковые поля растут |

Между крупными панелями — 32px. Внешние поля от 1056px — 32px. Вложенный текст не растягивай на всю ширину экрана. Круг — 220px, на компактном desktop — 200px. Не масштабируй весь интерфейс через transform: scale.

Мобильные и планшетные макеты, touch-навигация и отдельное мобильное меню не входят в объём. Не определяй компоновку по user agent.

При сужении окна desktop ниже 1024px и увеличении масштаба используй безопасное перестроение в одну колонку. Не блокируй приложение экраном «Откройте на компьютере». Дай прокручивать страницу по вертикали, переноси кнопки и длинные строки. Это поддержка узкого окна и увеличения масштаба, а не отдельная мобильная версия.

При высоте окна 720px действия должны быть доступны через обычную прокрутку. Не задавай фиксированную высоту панели с обрезкой. Если действия закреплены, они не должны закрывать поле ввода, уведомления и сфокусированный элемент.

## DES05. Читаемость и производительность

Проверяй контраст на итоговом фоне после смешивания прозрачных слоёв. Цели приёмки: не менее 4.5:1 для обычного текста, 3:1 для крупного текста и значимых границ элементов. Измеряй худший участок градиента под текстом. При недостаточном контрасте увеличь непрозрачность панели.

Если backdrop-filter недоступен, используй сплошной app-solid-surface с границей и тенью. При forced-colors используй системные цвета и видимые границы. При prefers-reduced-transparency, если он поддерживается, отключи прозрачность. В тестовой галерее должен быть способ проверить непрозрачный fallback независимо от поддержки настройки ОС.

Не анимируй blur, тени и большие фоновые пятна. Анимируй только круг и необходимые переходы из UX. При reduced motion сохраняй состояние без пульсации. Проверяй фокус на стекле и в модальных окнах.

## DES06. Материалы для реализации и проверки

До полировки экранов создай локальную галерею компонентов и состояний. Она доступна в режиме разработки и не входит в основной пользовательский путь. Storybook допустим, но не обязателен.

Галерея должна содержать: панель, кнопки во всех состояниях, поля с ошибками, уведомления, пустые состояния, круг 0/12.5/50/100%, запись, ожидание, offline и непрозрачный fallback. Используй детерминированные данные без вызовов платных API.

В docs/design-implementation.md агент фиксирует версии Carbon, токены, список собственных компонентов, отклонения от Carbon, проверенные viewport и результаты проверки контраста. Для каждого состояния из docs/11-interface-states.md укажи место реализации и способ воспроизведения.

## Анимация кругового индикатора

Геометрия, слои, связь с ответами и точные параметры переходов заданы в [спецификации анимации](12-progress-animation.md). Это собственный SVG-компонент в системе Carbon. Состояния ожидания используют Carbon; они не заменяют накопленный прогресс.
