# Анимация кругового индикатора: референс Apple Face ID

Версия: 1.2. Статус: обязательная спецификация для Claude. Анимация ещё не реализована и не измерена.

## MOT01. Назначение и референс

Круг показывает, насколько собраны требования к вакансии. Он заполняется по мере подтверждения содержательных ответов. Анимация помогает увидеть результат действия и сохраняет связь между этапами.

Визуальный референс — экран настройки Face ID с кругом вокруг центральной области. Apple описывает завершение круга в процессе настройки: [официальная инструкция Face ID](https://support.apple.com/en-us/108411). Для этого проекта используем круговую композицию, короткие радиальные штрихи и плавное проявление заполненных участков.

Это адаптация референса под голосовой бриф. Число штрихов, размеры, цвета, длительности и кривые ниже — проектные решения. Они не являются измерениями оригинальной анимации Apple. Камера, изображение лица, биометрия и второй проход сканирования не нужны.

В коде называй компонент VacancyProgressRing. Термин «лоадер» допустим в обсуждении, но компонент выполняет три разные функции:

1. Основное кольцо хранит подтверждённую полноту.
2. Внешний ореол показывает уровень голоса при записи.
3. Индикатор рядом с подписью показывает ожидание обработки.

У каждой функции отдельный источник состояния. Время и громкость не влияют на полноту.

## MOT02. Форма и слои

Используй SVG с viewBox 0 0 220 220. Размер на desktop — 220×220 CSS px; на компактном desktop — 200×200 CSS px. При изменении размера сохраняй пропорции. Центр и размер круга не меняются при переходе между вопросами.

Слои от нижнего к верхнему:

- Неподвижная нейтральная дорожка из 64 радиальных штрихов.
- Акцентные копии штрихов, видимые только в подтверждённых участках.
- Внешний тонкий ореол для записи; он не касается основной дорожки.
- Центральный текст «Полнота» и числовой процент.

Четыре сектора соответствуют q1, q2, q3, q4 по часовой стрелке, начиная сверху. Каждый сектор содержит 16 штрихов и две фиксированные группы по 8 штрихов. Каждая группа соответствует одной смысловой единице из semantics.

Предлагаемая точная геометрия:

- Центр SVG: (110,110).
- Штрих: радиальная линия от радиуса 88 до 98; ширина 2; концы круглые.
- На сектор отведено 90°: 84° для штрихов и 6° между секторами.
- Для сектора q с индексом 0–3 начало равно −87° + 90° × q. Здесь 0° направлен вправо, положительное направление — по часовой стрелке.
- Угол штриха j с индексом 0–15: начало + (j + 0.5) × 84° / 16.
- Ореол: радиус 104; ширина 1.5; максимальный scale 1.03, без обрезки краёв.

Пустая дорожка использует нейтральный цвет Carbon с видимым контрастом на стекле. Заполненные штрихи используют app-accent. Стеклянная поверхность и статичная мягкая тень находятся в панели, не в каждом штрихе. Само кольцо не размывай. Не создавай 64 свечения или фильтра.

Под кругом размести «Проверено ответов: N из 4». Во время записи добавь статус и таймер рядом с управляющей кнопкой. Не заменяй процент таймером: пользователь должен видеть накопленный прогресс.

## MOT03. Источник прогресса

Формула и критерии смысловой полноты заданы в [semantics](03-semantics.md). Не меняй их внутри анимационного компонента.

| Сектор | Первая группа штрихов | Вторая группа штрихов |
|---|---|---|
| q1 | q1.task1 | q1.task2 |
| q2 | q2.project | q2.contribution |
| q3 | q3.direction | q3.project |
| q4 | q4.tools | q4.knowledge |

Каждая действительная подтверждённая единица заполняет 8 штрихов и даёт 12.5%. Полный вопрос заполняет 16 штрихов и даёт 25%.

Вход компонента — восемь булевых значений validConfirmedUnits в фиксированном порядке таблицы. Они уже учитывают подтверждение, источники, конфликты и зависимости. Компонент получает также stage, activeQuestionId, answeredCount, audioLevel, connectionState и reducedMotion. Процент вычисляй из тех же восьми значений. Не передавай независимый произвольный percent, который может расходиться с секторами.

На экране показывай целое значение через Math.round. В расчётах сохраняй точное число: 12.5 → «13%», 37.5 → «38%», 62.5 → «63%», 87.5 → «88%». Числовую подпись обновляй сразу на целевое значение; штрихи догоняют его за 400 ms. Не прокручивай цифры от нуля при каждом обновлении.

Заполнение привязано к конкретным единицам. Если q1 пропущен, а q2 заполнен, светится сектор q2. Не переноси его штрихи в сектор q1 ради непрерывной дуги. Если известна только вторая единица вопроса, светится вторая половина сектора. Поэтому для корректной отрисовки недостаточно одного числа процента.

Предварительный анализ, длинная запись, нажатие «Далее» и ответ «не знаю» не дают заполнение. После правки источника недействительные единицы могут погаснуть. Сетевой сбой сам по себе единицы не удаляет.

## MOT04. Заполнение после ответа

Событие запуска: пользователь подтвердил проверенные факты, изменился validConfirmedUnits.

Для каждой новой единицы плавно прояви её группу по часовой стрелке. Покажи последовательное прохождение по восьми штрихам, а не мгновенную смену всего сектора. Ранее подтверждённые группы остаются неподвижными.

Длительность одного изменения — 400 ms. Кривая: cubic-bezier(0.22, 1, 0.36, 1). Начало быстрое, завершение плавное. Без отскока и превышения целевого заполнения.

Если одним подтверждением изменилось несколько групп, запускай их одновременно. Не увеличивай общую задержку до 400 ms на каждую группу. Внутри каждой группы движение идёт по часовой стрелке.

Для реализации используй локальную SVG-маску каждой группы: нормализованный reveal от 0 до 1 открывает акцентные штрихи по дуге. Нейтральные штрихи под маской всегда видны. Можно анимировать stroke-dashoffset маски. Это ограниченная перерисовка небольшого SVG; проверь её производительность. Не вращай всё основное кольцо и не меняй геометрию штрихов при заполнении.

При потере действительности единицы уменьши её reveal до 0 за 240 ms с той же кривой, погашая её в обратном порядке. Целевой процент снижается сразу. Рядом покажи причину, например «Ответ изменён. Проверьте сведения ещё раз». Простая навигация назад не снижает полноту.

При первоначальном показе уже существующего состояния отобрази его сразу. Не проигрывай накопленное заполнение заново после монтирования, навигации или восстановления видимости вкладки.

## MOT05. Запись голоса

Ореол появляется за 120 ms после реального начала записи. Нажатие кнопки и запрос разрешения ещё не означают запись.

Подавай в audioLevel нормализованную амплитуду 0–1 из Web Audio. Не генерируй случайные значения для имитации речи. Сглаживай сигнал по времени: ориентир attack 60 ms, release 180 ms. Порог тишины и нормализацию проверь на реальном микрофоне; не называй громкость показателем смысловой полноты.

Отображение: scale = 1 + 0.03 × audioLevel; opacity = 0.2 + 0.3 × audioLevel. Двигается только ореол. Основные штрихи, процент и текст не масштабируются. При тишине ореол остаётся тонким и неподвижным. Статус «Идёт запись» и таймер продолжают работать.

По stop, отмене, потере трека или выходу из записи останови измерение сигнала. Ореол исчезает за 120 ms. Запись завершается сразу; анимация исчезновения не удерживает микрофон открытым.

Если сеть пропала во время записи, локальная запись и ореол продолжаются до остановки или лимита. Покажи сетевое сообщение отдельно. Если микрофон недоступен, ореол не появляется.

## MOT06. Обработка и ожидание

В transcribing, analyzing и generating основное кольцо остаётся на текущем подтверждённом значении. Ореол голоса выключен. Под кругом показывай один Carbon InlineLoading с точной подписью этапа. Используй штатную анимацию Carbon выбранной версии; не создавай рядом второй вращающийся спиннер.

Не используй вращение заполненных секторов, бегущий акцент по пустым штрихам, автоматическое заполнение до 90% или обнуление круга. Нельзя смешивать неопределённую длительность запроса с полнотой ответов.

Подпись этапа меняется через opacity за 120 ms. Индикатор ожидания появляется, только если операция длится более 150 ms. Текст этапа меняется сразу. Если ответ пришёл раньше, не показывай краткую вспышку спиннера. Не вводи минимальное время ожидания ради анимации.

После 10 секунд действует сообщение S15. По ошибке, отмене или тайм-ауту цикл ожидания завершается. Результат запроса не должен ждать конца анимации.

## MOT07. Состояния и приоритеты

| Состояние | Основной круг | Дополнительное движение | Текст |
|---|---|---|---|
| Начало | Все штрихи нейтральные, 0% | Нет | «Ответьте на четыре вопроса» |
| Готов к ответу | Текущие подтверждённые группы | Нет | Вопрос и призыв записать ответ |
| Разрешение микрофона | Без изменения | Нет реакции на голос | «Разрешите доступ к микрофону» |
| Запись | Без изменения | Ореол от настоящего сигнала | «Идёт запись» и таймер |
| Обработка | Без изменения | Carbon InlineLoading | Название этапа |
| Проверка ответа | Без изменения до подтверждения | Нет | «Проверьте сведения» |
| Подтверждение новых фактов | Проявляются только новые группы | Однократный проход 400 ms | Новый процент |
| Нужны уточнения | Частичное заполнение сохранено | Нет | Одно уточнение |
| Ошибка / timeout | Подтверждённые группы сохранены | Ожидание выключено | Причина и действие повтора |
| Нет сети во время записи | Заполнение сохранено | Ореол работает локально | Запись + сообщение о связи |
| Нет сети после сбоя запроса | Заполнение сохранено | Нет ожидания без активного запроса | Повтор доступен |
| Редактирование с потерей фактов | Погасают только недействительные группы | Обратный проход 240 ms | Причина снижения |
| Полнота 100% | Все 64 штриха заполнены | Один короткий знак подтверждения | «Данных по четырём вопросам достаточно» |
| Неполный документ готов | Реальная полнота сохранена | Нет ложного завершения круга | «Черновик готов. Есть пропуски» |
| Повторная генерация | Текущая полнота сохранена | Только InlineLoading | «Составляем описание вакансии» |

Приоритет: сигнал реального микрофона определяет ореол; активный сетевой запрос определяет ожидание; validConfirmedUnits определяет штрихи. ConnectionState не отменяет локальную запись. Терминальная ошибка завершает только связанное ожидание. Эти состояния не заменяют друг друга одним глобальным флагом loading.

## MOT08. Завершение и переходы

Когда полнота впервые становится 100%, сначала заверши проявление штрихов. Затем прояви маленькую Carbon-иконку подтверждения над процентом за 180 ms через opacity. Круг остаётся в app-accent. Для иконки используй семантический цвет success. После появления иконка статична. Без конфетти, звука, вспышки и масштабирования всей панели.

100% означает достаточность по четырём вопросам, а не завершение генерации документа. Название должности и условия могут ещё требовать уточнения. Кнопка генерации доступна по бизнес-правилам сразу, независимо от завершения движения.

Если пользователь переходит к следующему экрану до завершения эффекта, отмени декоративное завершение. Не задерживай навигацию. Если полнота снизилась, убери знак подтверждения; при повторном достижении 100% покажи его без повторного праздничного эффекта. «Начать заново» сбрасывает флаг первого достижения.

Круг остаётся одним устойчивым компонентом при переходе между четырьмя вопросами. Его позиция не скачет из-за разной длины текста. Смена вопроса: opacity и translateY до 8px за 180 ms. Фокус и доступность кнопок не ждут анимации.

## MOT09. Прерывание и управление ресурсами

При новом целевом значении прерви текущую анимацию соответствующей группы и продолжи от фактически отображаемого reveal. Не начинай с 0 и не воспроизводи очередь устаревших состояний. Отмени старый обработчик completion, чтобы он не показал знак успеха после снижения полноты.

Предпочитай CSS transitions или WAAPI. SVG-геометрия неизменна. Не используй transition: all, изменение width/height или покадровый setState всей формы. JS нужен для чтения аудиосигнала и управления состоянием, а не для перерендера страницы на каждом кадре.

В скрытой вкладке и вне видимой области приостанови декоративное движение и чтение сигнала для визуализатора. Это не должно останавливать начатую запись: запись управляется отдельным жизненным циклом. При возвращении сразу покажи актуальную полноту и текущий уровень; не проигрывай пропущенные кадры.

При stop и unmount останови соответствующие media tracks, AudioContext/узлы визуализатора, requestAnimationFrame, наблюдатели и таймеры. Уход со страницы должен выполнять очистку. Сетевые события сами по себе не закрывают микрофон.

## MOT10. Доступность и производительность

У обёртки круга: role=progressbar, aria-valuemin=0, aria-valuemax=100, aria-valuenow с точной полнотой и доступное имя «Полнота требований к вакансии». aria-valuetext может сообщать «Подтверждено 5 из 8 частей; полнота 63 процента». SVG-штрихи декоративные; их не читает screen reader.

Прогресс не является интерактивным элементом и не попадает в Tab-порядок. Операция обработки имеет отдельную подпись состояния. Объявляй новое подтверждённое значение один раз, а не каждый кадр. Не дублируй встроенные объявления Carbon.

При prefers-reduced-motion: обновляй штрихи сразу; отключи изменение масштаба ореола и движение масок; покажи статичную отметку записи и текст ожидания. Обеспечь статичный вариант Carbon-индикатора на уровне приложения, если выбранная версия не предоставляет его. Поведение и доступные действия остаются прежними. Учитывай изменение настройки во время работы, в том числе для JS-анимации.

При forced-colors заполненные группы используй в системном Highlight, незаполненные показывай контуром с нейтральным системным цветом. Процент и подписи остаются текстовыми. При отсутствии blur непрозрачная панель не меняет геометрию круга.

Цель: плавное заполнение на экране 60 Hz; визуализатор допустим на 30–60 Hz. Это целевые показатели до измерения. В Chrome и Safari запиши 10 секунд записи и несколько подтверждений. Укажи устройство, версии браузеров, длительность кадров и найденные рывки. Не утверждай «60 FPS» без измерений. Декоративный цикл не работает в idle, review, error и после завершения.

## MOT11. Контрольный сценарий

1. Открыть первый вопрос: 0%, нет непрерывного движения.
2. Записать одну задачу: ореол реагирует, полнота остаётся 0%.
3. Завершить запись: ореол исчезает; при ожидании появляется InlineLoading.
4. Получить анализ: полнота ещё 0%.
5. Подтвердить одну задачу: 8 штрихов q1 проявляются за 400 ms; подпись 13%.
6. Дополнить и подтвердить вторую задачу: ещё 8 штрихов; 25%.
7. Подтвердить полный q2: сектор q2 проявляется; 50%.
8. Пропустить q3 и подтвердить полный q4: 75%; сектор q3 остаётся пустым.
9. Заполнить q3: 100%; затем появляется знак подтверждения.
10. Сгенерировать документ: 100% остаётся; ожидание показано отдельно.
11. Изменить q1 и удалить обе подтверждённые задачи: q1 гаснет; полнота 75%.
12. Повторить сценарий с reduced motion: значения и действия те же, пространственного движения нет.

## MOT12. Что Claude должен предоставить

- Компонент VacancyProgressRing и централизованные motion-токены.
- Примеры всех состояний MOT07 в галерее разработки.
- Пример разреженного заполнения: q1 и q3 пустые, q2 и q4 полные.
- Управление audioLevel в галерее для проверки 0, 0.5 и 1 без микрофона; в live — только реальный сигнал.
- Проверки, что запись, ожидание и ошибки не меняют подтверждённую полноту.
- Проверки смены цели во время анимации, reduced motion и очистки ресурсов.
- Короткую запись реализованной анимации и отчёт замеров. Пока реализации нет, не отмечай проверки как выполненные.

Критерий соответствия референсу: пользователь видит устойчивый круг из коротких штрихов, постепенное заполнение по ответам и спокойные переходы. Обычный вращающийся спиннер без накопленного заполнения этому требованию не соответствует.
