# Генерация описания вакансии

## Вход и выход

Вход: только подтверждённые актуальные факты без неразрешённых противоречий и список пробелов. Факты из conflicts и зависимые от них факты исключаются. Если остаются другие подтверждённые факты, можно создать неполный черновик. Перед генерацией сервер пересчитывает полноту. При отсутствии фактов верни INSUFFICIENT_FACTS.

Выход: JSON по vacancy.schema.json. Интерфейс строит из него текст. Разделы всегда идут в порядке: ежедневные задачи, текущий проект, следующие полгода, инструменты, знания. Пустой раздел выводит «Не указано». Поле gaps хранит вопросы, которые требуют уточнения.

Заголовок по умолчанию — «Описание вакансии». Если пользователь явно назвал должность, можно использовать её как заголовок с sourceFactIds. Не выводи должность из набора инструментов.

На экране покажи: заголовок, пять разделов, затем «Нужно уточнить». Последний блок не является частью утверждений о вакансии.

## Ограничения содержания

Перефразируй кратко. Удали слова-паразиты. Объедини точные повторы. Сохрани числа, названия, отрицания, обязательность и сроки. Не превращай «желательно» в «обязательно».

Не добавляй стаж, seniority, образование, зарплату, формат работы, офис, льготы, компанию и условия. Если эти сведения не названы, укажи их в gaps только как данные для возможного дополнения. Они не уменьшают полноту четырёх вопросов.

Каждый фактический пункт содержит sourceFactIds. Проверка ссылок ловит отсутствующий источник, но не любую смысловую галлюцинацию. Для смысловой проверки используй контрольные примеры и обзор пользователя. Если модель нарушает правила, повтори один раз в пределах бюджета. Затем верни ошибку, не подставляй выдуманный текст.

## Редактор и экспорт

Пользователь может редактировать заголовок и пункты. После ручной правки пометь результат «Изменено вручную». Не заявляй, что изменённый текст проверен по источникам. Сохрани исходную сгенерированную версию отдельно в памяти.

После изменения ответов пометь документ «Ответы изменились. Обновите описание». Повторная генерация не должна молча стирать ручные правки: предложи заменить текст или отменить действие. Экспорт устаревшего результата разрешён только после явного подтверждения с этим предупреждением.

Копирование и Markdown-экспорт используют текущий текст редактора. Рендери текст безопасно, без исполнения HTML. Имя файла: vacancy-description.md.

## Контрольный пример

Ответы:

1. «Ежедневно анализирует отказы оплаты и проверяет отчёты по конверсии».
2. «Работает над платёжным модулем магазина. Его задача — найти причины неуспешных платежей».
3. «Следующие полгода продолжит этот же платёжный модуль».
4. «Нужны SQL и Metabase, знание воронок оплаты. Python желателен».

Допустимое описание:

> **Описание вакансии**
>
> **Ежедневные задачи**
> - Анализировать отказы оплаты.
> - Проверять отчёты по конверсии.
>
> **Текущий проект**
> Платёжный модуль магазина. Вклад сотрудника — выявлять причины неуспешных платежей.
>
> **Следующие полгода**
> Продолжить работу над платёжным модулем.
>
> **Инструменты**
> SQL и Metabase. Знание Python желательно.
>
> **Знания**
> Знание воронок оплаты.
>
> **Нужно уточнить**
> Название должности и условия работы не указаны.

Недопустимо: «Ищем senior аналитика с опытом от трёх лет на удалённую работу». Эти данные отсутствуют во входе.
