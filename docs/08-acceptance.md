## Стратегия

Unit: полнота, зависимости, инвалидация, источники, разрешённые состояния.
Integration: маршруты, лимиты, provider adapters, тайм-ауты, некорректные ответы.
E2E в demo: основной путь, правка, уточнение, экспорт, ошибка, устаревший ответ.
Manual live: реальный микрофон в Chrome и Safari; русский язык; итоговая генерация.

Для AI-eval используй fixtures/cases.json. Прогони каждый текстовый случай три раза через live-анализ. Проверяй инварианты и ожидаемые состояния; не сравнивай литературный текст посимвольно. Зафиксируй модель, версию промпта, дату, результаты и пример ошибки. Три прогона — ограниченная проверка, не статистическое доказательство качества.

Для STT добавь собственные синтетические голосовые примеры без персональных данных: тихая комната, фоновый шум, названия SQL/Metabase, тишина. Ожидай сохранение ключевых названий; дай исправить ошибку. Текстовые фикстуры не проверяют качество распознавания голоса.

## Доказательства уровня max

Сохрани отчёт проверок и скриншоты: запись, частичная полнота, уточнение, обзор, результат. Для live приложи обезличенные события этапов с requestId, длительностью и моделью. Не прикладывай секреты или чужое аудио. Можно записать короткую демонстрацию; она не заменяет тесты.

## Демонстрация на пять минут

1. Покажи live-режим и начальный круг.
2. Дай один неполный голосовой ответ. Покажи текст и уточнение.
3. Добавь вторую задачу. Подтверди факты. Покажи рост полноты.
4. Пройди остальные вопросы с контрольным примером.
5. Открой обзор. Покажи источник одного факта.
6. Создай описание. Покажи структуру и отсутствие выдуманных условий.
7. Исправь пункт и скачай Markdown.
8. Покажи CLAUDE.md, схемы, план и отчёт проверок.

## Definition of Done

Все R01–R17 реализованы. Обязательные автоматические проверки проходят. Ручные live-проверки выполнены либо конкретно отмечены как блокировка. README и журнал состояния актуальны. Ошибки не скрыты. При блокировке live итог обозначается как «готов demo, live не подтверждён».
