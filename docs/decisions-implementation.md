# Решения реализации

Дата: 3 ноября 2026 года. Спецификация комплекта v1.2 не изменялась. Здесь записаны решения, которые спецификация оставила агенту, и расхождения с ней. Формат — по разделу «Изменение спецификации» в [09-decisions.md](09-decisions.md).

## Среда и версии

| ID | Решение | Причина |
|---|---|---|
| I01 | Node 22.23 LTS, `.nvmrc` = 22, `engines >=22.12` | Версия установлена у разработчика и в облачной среде. Node 24 не проверялся |
| I02 | TypeScript 6.0.3 вместо 7.x | typescript-eslint 8.72 поддерживает TypeScript `<6.1` |
| I03 | Точные версии в `package.json` и `package-lock.json` | Требование 04-architecture: без плавающих версий |
| I04 | Сервер собирается `vite build --ssr` в `dist/server/index.js` | Один сборщик для клиента и сервера; общий код `src/shared` без дублирования |
| I05 | `.env` читается `process.loadEnvFile` (Node 22) | Без лишней зависимости; переменные окружения имеют приоритет над файлом |

## Семантика и данные

| ID | Решение | Причина и ограничение |
|---|---|---|
| I10 | ID факта = `f_` + 16 hex SHA-256 от (вопрос, вид, нормализованный текст, источники с ревизией, ID зависимостей) | «ID фактам назначает сервер»; подтверждение сохраняется только при точном совпадении канонического содержания, источников и зависимостей. Правка ответа меняет ревизию → новый ID → нужно новое подтверждение; зависимые факты q3 получают новый ID автоматически |
| I11 | Единица засчитывается, если хотя бы один её факт пригоден (подтверждён, источник актуален, нет противоречия, зависимости пригодны) и ни один её факт не в противоречии | Формулировка 03-semantics («факты подтверждены») допускает два прочтения. Выбрано такое: пользователь может исключить один из двух фактов «инструментов» и не потерять единицу. Исключение всех фактов единицы гасит её |
| I12 | Пробелы (`gaps`) вычисляет сервер: незаполненные единицы, «Название должности не указано.», «Условия работы не указаны.» | Детерминированный и проверяемый список; модель не может добавить или убрать пробел. Совпадает с `fixtures/vacancy.full.json` |
| I13 | Сервер при генерации пересчитывает канонические ID фактов | Выявляет подмену текста факта клиентом (400) |
| I14 | Эвристика «не выдумано»: в документе нет чисел и признаков условий (зарплата, стаж, уровень, формат, льготы, образование, компания), которых нет в подтверждённых фактах | Ловит явные случаи T13/T11; не любую смысловую галлюцинацию. При срабатывании — один repair, затем `INVALID_MODEL_OUTPUT` |
| I15 | Разделы документа в другом порядке сервер упорядочивает; повтор или отсутствие раздела — ошибка | Порядок — формальное требование; содержимое не меняется |
| I17 | Один факт не может закрывать `q1.task1` и `q1.task2`; demo объединяет повтор того же сведения в один факт с несколькими источниками | «q1.task2 — вторая отличающаяся задача» (03-semantics) |
| I16 | Цитата ищется после нормализации Unicode NFC, пробелов и регистра; буквы (в том числе «ё») не заменяются | Цитата остаётся дословной; модель не может исправить текст пользователя |

## Контракты API: расширения версии 1.0

Все расширения обратно совместимы и задокументированы в Zod-схемах `src/shared/schemas.ts`.

| ID | Расширение | Причина |
|---|---|---|
| C01 | `source: "fixture" | "provider"` в ответах transcribe, analyze, generate | Интерфейс честно помечает данные demo («Ответ из тестового сценария») |
| C02 | Код ошибки `DEMO_UNSUPPORTED_TEXT` (422) | Demo не анализирует произвольный текст и не выдаёт выдуманный анализ (04-architecture) |
| C03 | `previousFacts` в `POST /api/analyze` (необязательно) | Только live: подсказка модели сохранить формулировки прежних фактов, чтобы ID и подтверждения не терялись. Сервер не доверяет этим данным и проверяет весь результат заново |
| C04 | `retryAfterSeconds` в теле ошибки и заголовок `Retry-After` для 429 | S17: «Если известна задержка, показать её» |
| C05 | `GET /api/config`: `live.sttConfigured`, `live.llmConfigured`, `llmModel`; в demo — `demo.scenarios` и `demo.catalog` | S24 до первой ошибки; выбор сценария demo. Ключи не передаются |
| C06 | Demo `POST /api/transcribe` без аудио, с полями `scenarioId`, `questionId`, `unitId` | 04-architecture: в demo запись только локальная, без отправки; сервер возвращает ответ сценария |

## Demo и live

| ID | Решение | Причина |
|---|---|---|
| D-1 | Demo-анализатор — каталог фиксированных результатов для текстов сценариев (`src/server/demo/catalog.ts`). Другие тексты → `DEMO_UNSUPPORTED_TEXT` | Не выдаёт тестовые данные за AI. Интерфейс предлагает подставить текст сценария или включить live |
| D-2 | Добавлен сценарий `guided` (одна задача + уточнение) и тексты уточнений/правок (T09, T10) | Демонстрация уточнения и смены проекта за пять минут без live |
| D-3 | Demo-генерация — шаблон: один пункт = текст подтверждённого факта. Подпись «Демо: шаблон без AI» | Детерминированный результат, совпадает с эталоном `vacancy.full.json` |
| D-4 | В live после обычной остановки запись отправляется сразу; после лимита или прерывания — по кнопке «Обработать записанное» | UX: «При достижении лимита … предложи обработать записанное» |
| D-5 | Live-провайдер без ключей возвращает `CONFIGURATION_ERROR`; режим не меняется | CLAUDE.md: «В live не переключайся на demo при ошибке» |
| D-6 | Идентификатор модели Anthropic в `.env.example` пустой | «Не придумывай идентификатор модели»; проверка доступности модели заблокирована отсутствием ключа |

## Интерфейс и анимация

| ID | Решение | Причина |
|---|---|---|
| U01 | Состояние сессии — внешний store (`useSyncExternalStore`), чистые переходы в `transitions.ts`, побочные эффекты в `controller.ts` | Проверяемые переходы (unit-тесты), отсутствие гонок при асинхронных ответах; галерея рендерит настоящие экраны из пресетов состояния |
| U02 | Уточнение предлагается после подтверждения (или сразу, если фактов нет — S05) | «После неполного ответа предложи уточнение»; подтверждённый прогресс виден до уточнения |
| U03 | Распознавание отправляется через XMLHttpRequest | Событие `upload.load` различает N03 «не удалось отправить запись» и N04 «не удалось получить ответ» |
| U04 | Событие `online` сбрасывает признак недоступности сервиса и показывает N07 | `navigator.onLine` — подсказка; платный запрос автоматически не повторяется |
| M01 | Маски групп — SVG `<mask>` с дугой и CSS-переходом `stroke-dashoffset`; длина дуги вычисляется без `pathLength` | Совместимость Safari. Проверено в Chromium через WAAPI: 400/240 ms, `cubic-bezier(0.22, 1, 0.36, 1)` |
| M02 | Знак 100%: `transition-delay` = длительность заполнения | «Сначала заверши проявление штрихов. Затем прояви иконку»; без JS-таймеров, прерывается снятием атрибута |
| M03 | Активный сектор подсвечен более тёмной нейтральной дорожкой (статично) | Пользователь видит, какой сектор относится к текущему вопросу; без движения |
| M04 | В скрытой вкладке у масок `transition: none`, ореол отписывается от сигнала | MOT09: при возвращении сразу актуальное состояние |
| S01 | Подключены только используемые стили Carbon (16 модулей компонентов + reset, grid, layout, layer, zone) и `:root { @include theme.theme() }` | CSS 1,23 МБ → 0,36 МБ; токены темы явно доступны на `:root` |

## Найденные и исправленные дефекты

- Проверка T30 обнаружила: после `online` баннер N01 оставался, потому что признак `serviceUnreachable` не сбрасывался. Исправлено в `controller.ts` (U04), тест проходит.
- Первые тесты T33/T36 измеряли время со стороны драйвера Playwright и давали ложные срабатывания. Замер перенесён внутрь страницы (rAF + `getAnimations()`), реальная анимация соответствовала спецификации.
- После сокращения CSS Carbon кнопки потеряли высоту и отступы: модуль `layout` с токенами `--cds-layout-size-height-*` не был подключён. Функциональные тесты это не поймали, дефект обнаружен при просмотре скриншотов. Модуль подключён, добавлен e2e-тест размеров и стилей Carbon (T25: основные кнопки 48 px, поля `field-01`).
