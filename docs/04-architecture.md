# Архитектура

## Выбранный стек

React + TypeScript + Vite + Carbon (@carbon/react): интерфейс. Кастомизацию темы и стеклянных панелей выполняй по docs/10-design-system.md. Node.js + Express: сервер. Zod: валидация. Vitest: модульные и интеграционные проверки. Playwright: браузерные сценарии. SVG + CSS: круг. Web Audio: уровень сигнала.

Это проектное решение для небольшого прототипа. При старте выбери поддерживаемые стабильные версии, совместимые с текущим Node.js LTS. Зафиксируй версии в package-lock.json и версию Node в .nvmrc. Не используй плавающие версии в инструкции запуска.

Структура: src/client, src/server, src/shared, tests/unit, tests/integration, tests/e2e, tests/evals. Схемы и правила полноты доступны обоим слоям. Сервер остаётся границей доверия.

## Провайдеры

Интерфейсы: Transcriber.transcribe(audio), Analyzer.analyze(snapshot), Generator.generate(confirmedFacts). Реализации: live и fixture. Клиент обращается только к своему серверу.

Для STT выбран Deepgram pre-recorded API, модель nova-3, язык ru. До интеграции проверь актуальную поддержку языка, контейнеров и лимитов. Для LLM выбран Anthropic Messages API с JSON Schema structured output. Идентификатор доступной модели задай через LLM_MODEL. Агент проверяет его доступность и фиксирует использованное значение в отчёте. Не придумывай идентификатор модели.

Документация провайдеров подтверждает поддержку русского языка у Nova-3 и структурированных ответов у Claude. Ссылки находятся в decisions. Структурированный формат не заменяет проверку фактов.

## Запись

Запрашивай getUserMedia только после нажатия. Проверь MediaRecorder.isTypeSupported: audio/webm;codecs=opus, audio/mp4, затем доступный браузерный формат. Передавай фактический recorder.mimeType. Если серверный провайдер не поддерживает формат, покажи понятную ошибку и текстовый ввод. Не переименовывай контейнер для имитации конвертации.

Для микрофона нужен безопасный контекст: HTTPS либо localhost. Проверяй поддержку API до показа кнопки. Обрабатывай отказ разрешения, отсутствие устройства, потерю трека и ошибку recorder. После stop дождись финального dataavailable перед отправкой.

Основные браузеры проверки: актуальные Chrome и Safari на macOS. Запиши точные версии. Поддерживается только desktop с адаптацией окна. Отдельные мобильные макеты и проверки мобильного микрофона не входят в объём.

## Состояние и хранение

Для прототипа используй состояние в памяти вкладки. Без базы данных и без постоянного хранения аудио. Сообщи на старте: «Ответы хранятся до закрытия или обновления страницы. Скачайте готовое описание».

Аудио хранится временно в памяти до успешной расшифровки или удаления пользователем. После этого освобождай Blob и object URL. Сервер не записывает аудио на диск. Тексты и черновик остаются до очистки сессии. Кнопка «Начать заново» запрашивает подтверждение удаления текущей работы.

В live до первой записи сообщи: «Аудио будет отправлено сервису распознавания. Текст будет отправлен сервису генерации». Не обещай удаление данных у провайдеров. Их условия хранения необходимо проверить перед использованием реальных данных.

## Надёжность

Каждый запрос содержит requestId и sessionRevision. Любое изменение активных ответов увеличивает sessionRevision. Применяй ответ только к совпадающей ревизии и активному requestId. Используй AbortController при отмене.

Тайм-аут каждого серверного вызова провайдера: 45 секунд. Для 429/5xx допускается один автоматический повтор с ограниченной задержкой, только внутри общего бюджета 45 секунд. После этого — явная ошибка. После невалидного ответа модели допускается один repair-вызов в том же бюджете. Не делай бесконечных повторов.

## Секреты и эксплуатация

Создай .env.example без значений секретов: APP_MODE=demo, PORT=3001, DEEPGRAM_API_KEY, ANTHROPIC_API_KEY, STT_MODEL=nova-3, STT_LANGUAGE=ru, LLM_MODEL.

Не используй префикс VITE_ для ключей. APP_MODE читает сервер; клиент получает режим через /api/config. В live отсутствие ключей даёт ошибку конфигурации. Demo не вызывает внешние сервисы.

Сервер: проверка размера до полного чтения, ограничение тела JSON 256 KiB, максимум 4000 символов на один ответ, максимум 12 активных ответов и 24000 символов на сессию. Ограничение аудио 10 MiB. Превышение возвращает ошибку до обращения к провайдеру. Ограничь частоту AI-запросов, например 20 в минуту на IP; значение вынеси в конфигурацию.

Для локальной сдачи сервер слушает loopback. Для публичного доступа нужны отдельные настройки доступа, расходов, TLS и хранения. Не называй прототип production-ready.

В логах: requestId, этап, длительность, код ошибки, режим, модель и версия промпта. Не логируй аудио, ответы, ключи и полный текст вакансии.

## Поведение demo

В demo пользователь выбирает контрольный сценарий из списка. Сервер возвращает фиксированные результаты для этого сценария. Показывай подпись «Ответ из тестового сценария». Не выдавай фиксированный текст за распознавание произвольной записи. Для проверки самого микрофона разрешена локальная запись и воспроизведение без отправки. Изменённый произвольный текст в demo не получает выдуманный AI-анализ: предложи выбрать сценарий или включить live.

Заглушки ошибок и задержек нужны для тестов. Не показывай технические переключатели ошибок в основном пользовательском сценарии.

## Соединение и состояние клиента

Реализуй соединение как отдельное состояние по docs/11-interface-states.md. Не удаляй текущий Blob при сетевом сбое. Не очищай текст после неудачного анализа. Ручной повтор использует тот же answerId и актуальную ревизию, но новый requestId. Отмена и поздние ответы не должны перезаписывать состояние. Гарантия сохранения действует только в живой вкладке; постоянное хранение и offline-first не добавляются.
