# Решения, допущения и источники

## Принятые решения

| ID | Решение | Причина и ограничение |
|---|---|---|
| D01 | Выход — описание вакансии | Соответствует бизнес-требованиям; слово «резюме» требует уточнения у заказчика |
| D02 | Запись отдельного ответа с обработкой после stop | Проще проверить; не требует потокового распознавания |
| D03 | Голос и текст используют один анализ | Ошибка микрофона не блокирует сценарий |
| D04 | Восемь единиц смысловой полноты | Прогресс объясним; это продуктовая рубрика, а не объективная оценка AI |
| D05 | Подтверждение фактов пользователем | Даёт возможность исправить ошибки распознавания и анализа |
| D06 | Stateless-сервер и память вкладки | Уменьшает объём прототипа; обновление страницы теряет сессию |
| D07 | Deepgram STT и Anthropic LLM | Разделяет голос и семантическую обработку; нужны два доступа |
| D08 | Явные demo и live | Позволяет проверять без ключей, сохраняя честную демонстрацию |
| D09 | Неполный черновик разрешён | Пользователь может не знать ответ; система явно показывает пробелы |
| D10 | Нет обязательного названия должности | Оно отсутствует в четырёх вопросах; заголовок остаётся нейтральным |

Пользователь подтвердил отсутствие ограничений по стеку и поручил выбрать его. Срок сдачи не задан. Временная оценка реализации не является обещанием.

## Проверенные технические источники

Дата проверки: 3 ноября 2026 года. Перед реализацией проверь совместимость выбранных версий SDK и моделей.

- [MDN: getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia): доступ к микрофону требует разрешения и безопасного контекста.
- [MDN: MediaRecorder.isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static): проверка поддержки MIME перед записью. Поддержка не гарантирует успех записи в любых условиях.
- [MDN: MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder): запись медиапотока и получение данных.
- [Deepgram: модели и языки](https://developers.deepgram.com/docs/models-languages-overview/): Nova-3 поддерживает русский; язык необходимо задать явно.
- [Deepgram: pre-recorded API](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded): интерфейс распознавания готовой аудиозаписи.
- [Anthropic: Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs): JSON-ответ по схеме. Выбранная модель и схема должны поддерживать этот режим.

Параметры дизайна, лимиты прототипа, число уточнений и формула полноты — решения этого комплекта. Они не взяты из задания или документации провайдеров.

## Изменение 1.1: требования пользователя к дизайну

Добавлены обязательные glassmorphism, Carbon с кастомизацией, desktop-only и адаптация окна. Прежний диапазон 360–1440px и обязательная мобильная компоновка отменены. Основной desktop-диапазон начинается с 1024 CSS px; при сужении окна и увеличении масштаба сохраняется безопасное перестроение. Это проектная интерпретация совместного требования «только desktop» и «адаптивный дизайн».

Обязательны нулевые, пустые и ошибочные состояния, потеря сети и восстановление. Добавлены docs/10-design-system.md и docs/11-interface-states.md; обновлены PRD, UX, архитектура, инструкции агенту, план и приёмка. Хранение остаётся в памяти вкладки.

Дополнительные первичные источники:

- [Carbon Themes](https://www.carbondesignsystem.com/building-blocks/foundations/themes/overview): настройка темы через токены.
- [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview): сетка и стандартные пороги.
- [Carbon Notification](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines): виды и поведение уведомлений.
- [MDN Navigator.onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine): ограниченная достоверность признака подключения.

Параметры стекла, desktop-минимум 1024px и состав экранов — решения проекта. Они не являются стандартными требованиями Carbon.

## Изменение 1.2: круговая анимация

Пользователь отдельно выделил требование Face ID-референса и заполнения по ответам. Добавлен docs/12-progress-animation.md. Выбраны 64 радиальных штриха, восемь фиксированных групп и раздельные слои голоса и ожидания. Заполнение выполняется после подтверждения содержательных ответов по прежней рубрике. Число штрихов и длительности — проектные решения, не измерения анимации Apple. Источник референса: [Apple Face ID setup](https://support.apple.com/en-us/108411).
