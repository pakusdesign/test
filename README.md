Исходный код в репозитории не содержит модели и исполняемые файлы других проектов. Для автономной работы используйте файлы выпуска, а не один только ZIP с исходным кодом GitHub.

# Локальное распознавание — обновление

Подключён whisper.cpp: речь можно преобразовать в текст без облачных ключей. [Установка и ограничения](docs/LOCAL-WHISPER.md). Анализ и генерация через Anthropic пока требуют отдельного подключения.

Веб-приложение задаёт четыре вопроса о работе будущего сотрудника. Ответ можно дать голосом или текстом. Система выделяет факты и показывает пробелы и противоречия. Пользователь проверяет и подтверждает сведения. После этого приложение собирает структурированное описание вакансии только из подтверждённых фактов. Описание можно отредактировать, скопировать и скачать в Markdown.

**Статус:** demo и локальный live работают. На Mac проверены реальные вызовы whisper.cpp и Ollama. Автономный пакет для Windows собирается отдельно в GitHub Actions; его нужно проверить на Windows перед тем, как заявлять полную поддержку платформы. Deepgram и Anthropic остаются дополнительными облачными провайдерами.

Спецификация комплекта v1.2 лежит без изменений: [KIT_README.md](KIT_README.md), [CLAUDE.md](CLAUDE.md), `docs/01–12`, `contracts/`, `prompts/`, `fixtures/`.

## Требования среды

- Node.js 22 LTS (проверено на 22.23.4; `.nvmrc`), npm 10.
- Desktop-браузер: актуальные Chrome или Safari. Ширина окна от 1024 CSS px; при более узком окне интерфейс перестраивается в одну колонку.
- Микрофон работает только на `localhost` или по HTTPS.
- Для локального live ключи не нужны. Облачные провайдеры Deepgram и Anthropic требуют свои ключи.

## Установка и запуск

**macOS, проще всего:** откройте папку проекта в Finder и дважды щёлкните `start.command`. Скрипт проверит Node.js, создаст `.env`, установит зависимости и откроет http://127.0.0.1:5173. Остановить — Ctrl+C в окне Terminal.

Вручную из Terminal (путь — к папке, где лежит этот README):

```bash
git clone https://github.com/pakusdesign/test.git
cd test
node -v                 # нужен 22.22.2+ в ветке 22; также 24.15+ или 26+; при nvm: nvm use
npm ci                  # зависимости из package-lock.json
cp .env.example .env    # по умолчанию APP_MODE=demo
npm run dev             # http://127.0.0.1:5173 (клиент) + http://127.0.0.1:3001 (API)
```

Production-сборка:

```bash
npm run build           # dist/client + dist/server/index.js
npm start               # http://127.0.0.1:3001 — сервер раздаёт собранный клиент
```

Сервер слушает только loopback (`HOST=127.0.0.1`). Прототип не готов к публичному размещению: нужны отдельные настройки доступа, TLS, лимитов расходов и хранения.

## Режимы

| Режим | Что происходит | Как включить |
|---|---|---|
| demo (по умолчанию) | Внешние сервисы не вызываются. Запись идёт локально: её можно прослушать, на сервер она не отправляется. Ответ подставляется из выбранного тестового сценария с меткой «Ответ из тестового сценария». Анализ — фиксированный результат каталога, только для текстов сценариев. На другой текст приложение отвечает «нет анализа» и ничего не выдумывает. Описание собирается шаблоном. В шапке постоянно видна метка «Демонстрация» | `APP_MODE=demo` |
| live | Запись отправляется в Deepgram (nova-3, ru). Анализ и генерация идут через Anthropic Messages API со structured outputs. Без ключей сервер возвращает `CONFIGURATION_ERROR`, и интерфейс показывает «Обработка сейчас недоступна». В demo приложение при этом не переключается | `APP_MODE=live` и ключи в `.env` |

Клиент узнаёт режим из `GET /api/config`. Ключи никогда не попадают в клиент: префикс `VITE_` не используется.

### Подключение live

1. Получите ключи Deepgram и Anthropic. Не отправляйте их в чат и не коммитьте.
2. Заполните `.env`:
   ```
   APP_MODE=live
   DEEPGRAM_API_KEY=...
   ANTHROPIC_API_KEY=...
   LLM_MODEL=<идентификатор модели, доступной вашему ключу>
   ```
   Идентификатор модели намеренно не задан. Возьмите его из списка моделей вашего аккаунта (https://docs.claude.com/en/docs/about-claude/models). Выбранная модель должна поддерживать structured outputs (`output_config.format`). Проверьте совместимость первым прогоном `eval:live`.
3. Запустите `npm run eval:live`. Каждый случай из `fixtures/cases.json` прогоняется 3 раза. Проверяются генерация и STT на синтетических голосовых примерах из `tests/evals/audio/`. Отчёт: `docs/evidence/live-eval.json`, модель и версия промпта записываются в отчёт.
4. Вручную проверьте запись в Chrome и Safari: `npm run dev` → «Записать ответ» → русская речь → расшифровка → уточнение → описание. Без живого голоса можно подать синтетическую речь в Chrome: `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=tests/evals/audio/fake-mic-q1.wav`.
5. Перед использованием реальных данных проверьте условия хранения данных у Deepgram и Anthropic. Приложение не обещает их удаление у провайдеров.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| APP_MODE | demo | `demo` или `live` |
| PORT / HOST | 3001 / 127.0.0.1 | Адрес сервера |
| DEEPGRAM_API_KEY | — | Ключ STT (только сервер) |
| ANTHROPIC_API_KEY | — | Ключ LLM (только сервер) |
| STT_MODEL / STT_LANGUAGE | nova-3 / ru | Параметры Deepgram |
| LLM_MODEL | — | Модель Anthropic; обязательна для live |
| LLM_MAX_TOKENS | 4096 | Лимит ответа модели |
| RATE_LIMIT_PER_MINUTE | 20 | AI-запросов в минуту на IP (live) |
| PROVIDER_TIMEOUT_MS | 45000 | Общий бюджет вызова провайдера, включая один повтор и один repair |

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер (tsx watch) и клиент (Vite) |
| `npm run typecheck` | TypeScript без сборки |
| `npm run lint` | ESLint, предупреждения запрещены |
| `npm test` | Unit-тесты (Vitest) |
| `npm run test:integration` | API, лимиты, провайдеры на подменённом HTTP, demo-конвейер по `cases.json` |
| `npm run test:e2e` | Playwright в Chromium с фиктивным микрофоном, demo |
| `npm run evidence` | Скриншоты галереи и пути, видео анимации, замеры кадров → `docs/evidence/` |
| `npm run check:contrast` | Контраст на итоговом фоне стекла → `docs/evidence/contrast.json` |
| `npm run eval:live` | Live-проверка (платные вызовы); без ключей — BLOCKED, код выхода 2 |
| `npm run build` / `npm start` | Сборка и запуск production-сервера |

Перед первым `test:e2e` нужен Chromium для Playwright 1.63.0: `npx playwright install chromium`.

## Архитектура

```
src/shared/     схемы Zod, полнота, проверка связей, Markdown, пробелы — общие для клиента и сервера
src/server/     Express 5: маршруты, лимиты, бюджет вызовов, ID фактов, провайдеры demo/live
src/client/     React 19 + Carbon: состояние сессии, запись, круг, экраны, галерея (dev)
tests/unit|integration|e2e|evidence|evals
```

Поток данных: аудио → STT → редактируемый текст → модель извлечения → сервер проверяет схему, цитаты, ревизии, зависимости и назначает ID → полнота считается в коде → пользователь подтверждает → в генерацию идут только пригодные подтверждённые факты → сервер проверяет документ → редактор → Markdown.

- **Граница доверия — сервер.** Он проверяет вход (Zod, лимиты до вызова провайдера), ответ модели (схема и связи, один repair) и происхождение фактов при генерации (канонические ID, ревизии, `sourceFactIds`, эвристика выдуманных условий).
- **Полнота** — 8 смысловых единиц по 12,5% (`src/shared/completeness.ts`). Модель процент не считает.
- **Состояние** живёт только в памяти вкладки. Обновление страницы теряет сессию, и приложение предупреждает об этом. Аудио хранится до успешной расшифровки или явного удаления.
- **Надёжность.** У каждого запроса есть `requestId` и `sessionRevision`. Поздние ответы отбрасываются. Ручной повтор отправляет новый `requestId` и не создаёт новый ответ. Автоматических повторов на клиенте нет.
- **Круг `VacancyProgressRing`**: 64 штриха, 8 групп-масок по 8 штрихов. Ореол голоса и InlineLoading ожидания — отдельные слои ([docs/design-implementation.md](docs/design-implementation.md)).

API: [docs/05-contracts.md](docs/05-contracts.md). Расширения контракта — в [docs/decisions-implementation.md](docs/decisions-implementation.md).

## Известные ограничения

- Live не подтверждён: нет ключей, реальные вызовы Deepgram и Anthropic и `eval:live` не выполнялись. Качество распознавания и извлечения не измерено.
- Проверки шли только в Chromium (headless, Linux). Chrome и Safari на macOS и реальный микрофон не проверены.
- Порог тишины и нормализация громкости ореола — стартовые значения. Их нужно откалибровать на реальном микрофоне.
- Замеры кадров получены в headless-среде без GPU. Это не доказательство 60 FPS на реальном экране.
- В live формулировки фактов могут меняться между анализами. Тогда ID факта меняется и подтверждение нужно повторить. Подсказка `previousFacts` снижает этот риск, но не исключает его.
- Эвристика «не выдумано» ловит числа и явные условия, но не любую смысловую неточность модели.
- Нет авторизации, постоянного хранения, PWA и offline-first. Без сети приложение не загружается (N10).
- Термин «резюме» из задания трактуется как описание вакансии (допущение A1).
